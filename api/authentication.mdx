AgyDesk uses session-based authentication powered by your dashboard login. When you call the REST API from a browser context, your active session cookie is sent automatically. For server-side scripts, CI pipelines, and daemon workers that run outside the browser, you authenticate by including the session token from your active login as a Bearer value in the `Authorization` header.

## How Authentication Works

AgyDesk does not issue standalone API keys from a settings page. Instead, your authentication credential is the session token issued when you sign in to the AgyDesk dashboard. You can obtain this token programmatically after signing in, then pass it with your API requests.

<Steps>
  <Step title="Sign in to AgyDesk">
    Navigate to [agydesk.com](https://agydesk.com) and sign in with your Google account. You are redirected to the dashboard after authentication completes.
  </Step>
  <Step title="Retrieve your session token">
    After signing in, open your browser's developer tools (F12), go to **Application → Local Storage → agydesk.com**, and find the `access_token` value stored under your session. Alternatively, if you are building a server-side integration, obtain the token by calling the AgyDesk auth client after your user signs in:

    ```typescript
    import { createClient } from "@supabase/supabase-js";

    const supabase = createClient(
      process.env.NEXT_PUBLIC_SUPABASE_URL!,
      process.env.NEXT_PUBLIC_SUPABASE_ANON_KEY!
    );

    const { data } = await supabase.auth.getSession();
    const token = data.session?.access_token;
    ```
  </Step>
  <Step title="Pass the token on every API request">
    Include the token in the `Authorization` header as a Bearer value:

    ```bash
    Authorization: Bearer <your-session-token>
    ```
  </Step>
</Steps>

## Example Request

The following example checks whether your workstation is online using your session token:

```bash
curl -s https://agydesk.com/api/workstation/status \
  -H "Authorization: Bearer <your-session-token>"
```

A successful response looks like:

```json
{
  "status": "online",
  "browser": "Chromium 133.0.6943.53",
  "protocol": "1.3",
  "userAgent": "Mozilla/5.0 (X11; Linux x86_64) AppleWebKit/537.36 ...",
  "wsUrl": "ws://localhost:9222/devtools/browser/xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx"
}
```

## Authentication Errors

| Status | Meaning |
|--------|---------|
| `401 Unauthorized` | The session token is missing or has expired — sign in again to get a fresh token |
| `403 Forbidden` | The session is valid but the account does not have permission for this action |

<Note>
  Keep your session token private. Never embed it in client-side JavaScript, commit it to a public repository, or include it in a browser URL. Treat it with the same care as a password. Session tokens expire automatically — re-authenticate to get a new one when yours expires.
</Note>

<Tip>
  For daemon workers and CI pipelines running server-side, store the token in an environment variable — for example `AGYDESK_SESSION_TOKEN` — and reference it at runtime rather than hardcoding the value.
</Tip>
